1. git init
Что делает? Превращает текущую папку в новый Git-репозиторий. Создается скрытая подпапка .git, где будет храниться вся история и настройки.

Когда использовать? Когда у вас есть новая папка с кодом (или без кода), и вы хотите начать отслеживать ее историю с помощью Git.

Пример использования:

bash
# Переходим в папку нашего проекта
cd /path/to/my/project

# Инициализируем новый репозиторий
git init

# Результат в терминале:
# Initialized empty Git repository in /path/to/my/project/.git/

2. git clone
Что делает? Создает копию удаленного репозитория (например, с GitHub или GitLab) на вашем локальном компьютере. Эта команда автоматически добавляет удаленный репозиторий под именем origin.

Когда использовать? Когда вам нужно скопировать существующий проект с удаленного сервера к себе на компьютер, чтобы начать с ним работать.

Пример использования:

bash
# Клонируем репозиторий по URL
git clone https://github.com/username/repository-name.git

# Репозиторий склонируется в папку 'repository-name'

# Можно также указать свое имя для папки
git clone https://github.com/username/repository-name.git my-folder-name

3. git add
Что делает? Добавляет изменения из рабочей директории в область подготовленных файлов (Staging Area). Это подготавливает их к следующему коммиту.

Когда использовать? После того как вы создали, изменили или удалили файлы и хотите зафиксировать эти изменения в истории.

Пример использования:

bash
# Создаем новый файл
echo "Hello World" > readme.txt

# Добавляем КОНКРЕТНЫЙ файл в staging
git add readme.txt

# Или добавляем ВСЕ изменения в рабочей директории (новые, измененные, удаленные)
git add .

# Или добавляем все файлы с расширением .js
git add *.js

4. git commit
Что делает? Сохраняет подготовленные изменения (из Staging Area) в историю репозитория. Каждый коммит имеет уникальный хеш, автора, дату и сообщение.

Когда использовать? Когда вы собрали в Staging Area логический набор изменений (например, добавили новую функцию или исправили баг) и готовы сохранить эту версию проекта.

Пример использования:

bash
# Коммитим подготовленные изменения с сообщением
git commit -m "Добавлен файл readme с приветствием"

# Результат в терминале:
# [main (root-commit) a1b2c3d] Добавлен файл readme с приветствием
#  1 file changed, 1 insertion(+)
#  create mode 100644 readme.txt

5. git push
Что делает? Отправляет ваши локальные коммиты в удаленный репозиторий (например, на GitHub). Это синхронизирует ваш локальный репозиторий с удаленным.

Когда использовать? Когда вы сделали один или несколько коммитов локально и хотите "расшарить" их своей команде или просто сохранить на удаленном сервере.

Пример использования:

bash
# Пушим изменения в удаленный репозиторий с именем 'origin' в ветку 'main'
git push origin main

# Если вы ранее установили upstream (связь) для вашей ветки, можно использовать просто:
git push

6. git pull
Что делает? Это комбинация двух команд: git fetch (загружает изменения из удаленного репозитория) и git merge (вносит эти изменения в вашу текущую ветку). Она получает и применяет последние изменения из удаленного репозитория к вашей локальной рабочей копии.

Когда использовать? Когда вы хотите обновить свою локальную версию проекта до последней версии, которая есть на удаленном сервере (например, ваши коллеги сделали push новых коммитов).

Пример использования:

bash
# Получаем и сливаем изменения из удаленного репозитория 'origin', ветки 'main'
git pull origin main

# Если ваша локальная ветка уже отслеживает удаленную, можно использовать просто:
git pull
